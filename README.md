# 龙头战法量化系统（Dragon Quant System）

把「机构行为」这个不可见变量，通过量价 / 资金 / 筹码 / 形态四维数据，
识别成四个可判别的阶段：**建仓 → 洗盘 → 启动 → 撤离**。

**项目位置**：`E:\wb_jobs\finance`

## 快速开始

```bash
# 1. 安装依赖（只需 requests + numpy）
pip install requests numpy

# 2. 分析指定标的
python -m dragon.cli codes 002463,300308,603986,600354 --history

# 3. 全市场自动扫描龙头候选池
python -m dragon.cli scan --top 8

# 4. 生成/更新行业龙头每日看板网站（每天跑这条）
python -m dragon.cli site --per 3 --out site
```

## 每日看板网站

`site` 命令产出 `site/index.html` + `site/klines.js` + `site/data.json`：
覆盖 20+ 个行业，每个行业按「市值排名 40% + 主力资金排名 35% + 涨幅排名 25%」
选出 3 只龙头，逐只输出**阶段判定、四阶段得分、机会分、风险分、操作建议**。

特性：
- **零外部依赖**，不引任何 CDN，评分用纯 CSS、K线图用纯 SVG 手绘 —— 定时任务无人值守场景下最稳
- **首页关注榜**：左侧「最值得关注买入」（机会分前 5，剔除风险分 ≥60）、
  右侧「最值得卖出/撤离」（撤离期优先，其余按风险分前 5）
- **K线+成交量交互图**：点击任意标的弹出最近 100 个交易日 K 线
  （红涨绿跌、MA5/10/20 均线、成交量副图），鼠标悬停可查看每日
  开高低收、涨跌幅、换手率、成交量与成交额
- 支持按阶段筛选、按机会分/风险分/阶段分/涨幅排序、按名称搜索
- `data.json` 落盘完整数据；`klines.js` 为独立 K 线数据文件
  （file:// 协议下经典 `<script>` 无跨域限制，故不用 fetch 加载）

定时任务（每个交易日收盘后更新）已配置为自动化，见下方「定时更新」。

## 系统结构

```
dragon/
├── datasource.py   数据层：多源行情封装（东财/腾讯/新浪，含域名故障转移）
├── indicators.py   指标层：量能、价格、资金、筹码三角形模型、形态识别
├── stage.py        模型层：四阶段加权证据打分卡 ← 调参主要在这里
├── analyzer.py     流水线：原始数据 → 特征 → 判定结果；支持历史回放
├── screener.py     选股层：全市场三层漏斗筛出龙头候选池
├── industry.py     行业层：板块→成分股→龙头评分→机会/风险分
├── site.py         网站层：行业龙头每日看板（零依赖 HTML）
├── report.py       渲染层：HTML + ECharts 报告
└── cli.py          命令行入口
```

## 多源数据架构（关键）

部分网络环境下东财 `push2` / `push2his` 域名会被服务端彻底屏蔽（TCP 层
RemoteDisconnected），系统因此实现了**域名故障转移 + 多数据源兜底**：

| 数据 | 主源 | 兜底 |
|---|---|---|
| 日K线 | 东财 push2his | **腾讯行情**（前复权，成交额按典型价估算） |
| 实时快照/板块 | 东财 push2 | **push2delay**（延时服务器，域名池自动切换） |
| 资金流历史 | 东财 push2his | **新浪**（120日，中/小单置0）+ 东财延时当日拼接 |
| 龙虎榜 | 东财 datacenter-web | — |

- 域名黑名单：连接层错误（ConnectionError/ProxyError）的域名本次运行内直接剔除，
  不再浪费超时 —— 批量 70+ 标的时从 28s/只 降到 1.5s/只
- 新浪资金流口径与东财「主力净额」不同（新浪=净流入额），**相对指标
  （净流入率、超大单占比）跨源可比**，模型主要依赖相对指标，绝对值仅供方向参考

## 判定机制

每个阶段是一组**加权证据**，每条规则输出三态：`True / False / None(数据不足)`。

- 数据不足的项**自动剔除、不计入分母**，因此某类数据缺失时系统降权而非崩溃
- 阶段得分 = Σ命中权重 / Σ适用权重 × 100
- 每个阶段另设**门槛条件 gate**，不满足则总分打 62 折（避免误判）
- 取四阶段**最高分**作为判定结果，**置信度 = 最高分 − 次高分**
- 置信度 < 5 说明处于阶段切换的模糊带，报告会明确提示「等信号确认」

## 四阶段判据要点

| 阶段 | 核心矛盾 | 关键量化判据 | 操作取向 |
|---|---|---|---|
| 建仓 | 要买但怕抬价 | 资金逆势回流（主力净额占成交额>3%）、OBV抬升而股价横盘、深度超跌、位置中低位 | 跟踪观察，分批低吸 |
| 洗盘 | 要吓人但不能真卖 | 缩量下跌（量比<0.95）、未破MA60、底部筹码锁定>18%、主力流出占成交额<5% | 拿住，破关键位止损 |
| 启动 | 想快拉但需人跟 | 放量突破平台、站上MA20、均线多头、MACD红柱放大、超大单占主力>45%、上方套牢盘<22% | 主升持有，破MA20离场 |
| 撤离 | 要卖但怕崩 | 底部筹码上移/消失、主力净流出占成交额>2%、超大单出而小单接、乖离>22%赶顶、换手>18% | 减仓离场 |

## 调参

所有阈值集中在 `stage.py` 的 `RULES`（每阶段的证据规则）与 `GATES`（门槛条件）中，
每条规则自带 `weight` 与 `expect`（判据说明），报告会自动渲染出这张判据表。

建议按**市值与股性**分组调参：小市值题材股的换手阈值应显著高于大盘蓝筹。

## 已知的数据坑（已在代码中处理）

1. **盘中数据不完整**：15:00 前当日成交量只累计了半天，直接算量比会系统性偏低、造成「缩量」假象。系统自动以**上一完整交易日**为判定基准日。
2. **筹码/获利盘单位**：统一为百分数 0–100，阈值必须写成 `18` 而非 `0.18`。
3. **龙虎榜口径**：`BILLBOARD_NET_AMT` 是上榜当日**全部席位**净额（含机构与游资），不是纯机构净买额；且必须限制时间窗口，否则会累加跨年历史数据。
4. **市值单位**：东财 `f116/f117` 返回单位是**元**，需 ÷1e8 转亿元。
5. **MACD 语义**：「水上金叉」必须同时满足 DIF>DEA、红柱>0、红柱较前一日放大，否则水下金叉会被误判。
6. **接口限流**：需请求节流 + 指数退避 + UA 轮换 + 连接池重建，否则连续请求会 ConnectionError。
7. **域名屏蔽**：`push2`/`push2his` 在部分网络被 TCP 层屏蔽（非限流），必须多源兜底 + 域名黑名单，见上表。
8. **空响应陷阱**：push2delay 对历史 K 线返回「data 存在但 klines 为空」，直接判真会得到 0 根 K 线；必须校验 klines 非空。
9. **缓存污染**：失败响应不会写缓存，但「成功却为空」的响应会 —— 接口层逻辑变更后务必清 `.cache` 再回归。
